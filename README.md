# Pi session notes

Pi での会話を、次の相談や開発に引き継ぐためのノートにまとめる extension です。応答の完了後、現在のエージェントに背景、判断の理由、未解決事項などの記録を依頼します。既定ではセッションごとにノートを作成し、同じセッションの会話に応じて更新します。

## 導入

Node.js 22.19.0 以降と Pi が必要です。リポジトリを手元に用意し、利用するプロジェクトで次を実行します。

```sh
pi install -l /path/to/notes
```

`-l` はプロジェクトローカルへの登録です。Pi で `/reload` するか、Pi を再起動してください。会話が完了すると、作業ディレクトリの `_notes/<session_id>/note.md` に記録を依頼します。今すぐ記録するには Pi で `/note` を実行します。

## 保存先の設定

作業ディレクトリの `.pi/notes.json` に、ファイル名を含むパスを指定できます。

```json
{
  "path": "../shared-notes/{sessionId}.md"
}
```

`{sessionId}` は現在のセッション ID に置き換わります。相対パスは作業ディレクトリを基準に解決し、絶対パスと `~/` も使えます。`{sessionId}` を省くと、複数のセッションが同じファイルを更新します。

環境変数 `PI_NOTES_PATH` でも同じ形式で指定できます。優先順位は、空でない環境変数、設定ファイル、既定値の順です。設定ファイルを使う場合、内容が不正であればエラーを表示し、記録を開始しません。

```sh
PI_NOTES_PATH="/path/to/notes/{sessionId}.md" pi
```

## 記録の仕組みと注意点

- 自動記録は応答が完了した直後に行います。中断された実行は自動記録せず、ノート作成自身の完了では再発火しません。
- ノートはモデルが通常のファイルツールを使い、[procedure.md](procedure.md) に従って作成・更新します。会話の全文バックアップではなく、内容や保存成功は保証されません。失敗時の自動再試行はありません。
- 記録のために追加のモデル実行が発生し、時間と利用料金がかかります。ノート作成中の成功したツール表示は抑制しますが、履歴には残り、セッション再開後などに表示されることがあります。
- 手順では認証情報や不要な個人情報を転記しないようモデルに指示していますが、確実な除外は保証されません。ノートには会話内容やセッションファイルのパス、作業ディレクトリが含まれ得るため、保存先へのアクセスを制限し、Git 管理や共有の前にノートの内容を確認してください。
- `guard:trust-dir` イベントで、保存先ファイルの親ディレクトリをセッション開始時と保存依頼時に通知します。実際の許可範囲や動作は guard 側の実装と設定に依存します。

## テスト

```sh
npm test
```

テストはコマンドやイベントの処理、保存先の解決などを検証します。実際のモデルによる記録品質や guard との連携は検証しません。
