# Pi session notes

Pi での会話を、次の相談や開発に引き継ぐためのノートにまとめる extension です。応答の完了後、現在のエージェントに背景、判断の理由、未解決事項などの記録を依頼します。既定ではセッションごとにノートを作成し、同じセッションの会話に応じて更新します。

## 導入

Node.js 22.19.0 以降と Pi が必要です。リポジトリを手元に用意し、利用するプロジェクトで次を実行します。

```sh
pi install -l /path/to/notes
```

`-l` はプロジェクトローカルへの登録です。Pi で `/reload` するか、Pi を再起動してください。会話が完了すると、プロジェクトの `.pi/_notes/<session_id>/note.md` に記録を依頼します。今すぐ記録するには Pi で `/note` を実行します。

## 過去のノートを検索する

guard と同じ `GUARD_OPENAI_API_KEY` を環境変数に設定して Pi を起動し、「以前のノートから認証方式の決定を探して」のように依頼します。`search_notes` ツールがプロジェクトの `.pi/_notes` 以下にある Markdown を検索し、関連度の高い最大 5 件の抜粋とファイル名・行番号を返します。Factory や追加ノートもこのディレクトリ以下なら対象です。旧 `_notes/` を含め、別の保存先を指定しても検索範囲は広がりません。配下のシンボリックリンクはたどりません。

検索時は、ノートの本文と検索文を OpenAI の `text-embedding-3-large` に送信します。API 利用料金が発生し、ノートに秘密情報が含まれていればそれも送信されます。検索を依頼する前に対象を確認してください。ノートを Markdown の見出し（`#` 形式）で区切り、長い節は行のまとまりを優先して最大 1,200 文字に分けます。各部分をベクトル化し、検索文とのコサイン類似度で並べます。結果の関連性は保証されません。

ノートのベクトルと、直近 1,000 件の検索文のベクトルを `.pi/_notes/.notes-search-cache.json` に保存し、Pi の再起動後も再利用します。検索文は前後の空白を除いた完全一致で照合し、再利用した検索文も最新として扱います。ノートの変更・削除は次回検索時に反映します。ノートと検索文の両方がキャッシュにあれば、キーの設定や API 通信なしで検索できます。同じ検索を続けて実行し、ノートにも変更がなければキャッシュファイルを再保存しません。キャッシュを削除すると、次回は再取得のための送信と料金が発生します。

キャッシュには本文や検索文をそのまま保存せず、照合用のハッシュとベクトルを保存します。ただし、それらにも内容に関する情報が含まれ得ます。ファイルは所有者のみ読み書きできる権限で作成されますが、共有や Git 管理には含めないでください。同時に複数の Pi が検索すると、最後に保存したキャッシュが残るため、後で一部のベクトルを再取得する場合があります。

## 保存先の設定

起動したディレクトリから親へ順にたどり、ノート設定または `.git` が最初に見つかった場所をプロジェクトルートとします。どちらもなければ最も近い `.pi` の親、最後に起動ディレクトリを使います。ホームのグローバル設定は探索から除きます。旧 `_notes` のファイルは自動移動しません。以前と同じファイルに追記するには、旧パスを明示してください。

プロジェクトの `.pi/notes.json` に、ファイル名を含むパスを指定できます。

```json
{
  "path": "../shared-notes/{sessionId}.md"
}
```

`{sessionId}` は現在のセッション ID に置き換わります。相対パスはプロジェクトルートを基準に解決し、絶対パスと `~/` も使えます。`{sessionId}` を省くと、複数のセッションが同じファイルを更新します。

環境変数 `PI_NOTES_PATH` でも同じ形式で指定できます。優先順位は、空でない環境変数、設定ファイル、既定値の順です。設定ファイルを使う場合、内容が不正であればエラーを表示し、記録を開始しません。

```sh
PI_NOTES_PATH="/path/to/notes/{sessionId}.md" pi
```

## 任意の追加ノート

プロジェクトの `.pi/notes-extra.json` に、ファイル名と記録したい内容を自由に指定できます。

```json
{
  "documents": [
    { "path": "_notes/{sessionId}/decisions.md", "description": "決定事項とその理由" },
    { "path": "_notes/{sessionId}/handoff.md", "description": "次の担当者への引き継ぎ事項" }
  ]
}
```

追加ノートは `/note` の実行時だけ、該当する内容があれば作成・更新するようモデルに依頼します。通常のセッションノートは引き続き応答完了後にも記録します。追加ノートには、通常ノートと同じパスの解決方法、重複検出、既存内容の保全と以下の注意点が適用されます。設定が不正な場合や通常ノート・Factory の保存先と重複する場合、`/note` の記録依頼全体を開始せず通知します。

## Software Factory の記録

plan・review・learnings を分けて残すには、プロジェクトの `.pi/notes.json` に `"factory": {}` を追加します。通常の `note.md` に加えて、記録する内容がある分類だけを次に作成・更新するようモデルに依頼します。従来の `.pi/notes-factory.json` も引き続き利用でき、両方ある場合は `notes.json` の `factory` が優先されます。

```text
.pi/_notes/<session_id>/factory/plan.md
.pi/_notes/<session_id>/factory/review.md
.pi/_notes/<session_id>/factory/learnings.md
```

保存先は分類ごとに指定できます。未指定の項目は上記の既定値を使い、通常ノートの `path` や `PI_NOTES_PATH` には影響しません。

```json
{
  "plan": "../shared-notes/{sessionId}/plan.md",
  "review": "../shared-notes/{sessionId}/review.md",
  "learnings": "../shared-notes/{sessionId}/learnings.md"
}
```

通常ノートと同じく、相対パスはプロジェクトルート基準で、絶対パス、`~/`、`{sessionId}` を使えます。通常ノートを含む保存先が解決後に重複する場合や Factory 設定が不正な場合は、既存ノートの保全のため、その回の記録依頼全体を開始せずエラーを通知します。リンク先が未作成のシンボリックリンクや、既存のハードリンクによる重複も確認します。確認後にファイルやリンクが変更される場合まで重複を防ぐものではありません。

Factory の各ファイルは `/note` の実行時だけ更新対象です。既存ファイルを読み、出典と文脈を残して更新するよう指示します。分類や更新はモデルが行うため、内容や保存を保証するものではなく、複数ファイルの更新も一括処理ではありません。

親と子が引き継ぐときは、タスクに関連ファイルの絶対パス、対象の版、未解決事項を明示し、子は結果と出典を親に返してください。親は受け取った結果を自分の記録に反映できます。別 worktree では相対パスと設定ファイルがそれぞれのプロジェクトルートを基準に解決されます。子への設定・ファイル共有・結果の受け渡しは自動ではありません。複数のセッションやエージェントに同じ保存先を指定すると同時更新で内容を失う可能性があるため、セッションごとに分け、統合は親が行ってください。

## 記録の仕組みと注意点

- 各ノートは、既存の記録を残し、新しい情報を記録日時と出典付きで末尾に追記するようモデルに依頼します。新しい情報がなければ日時だけを更新しません。ファイル冒頭に明確な要約欄があれば、現在の状態を反映するために更新できます。既存ノートに要約欄がない場合、既存本文はそのまま残します。
- 自動記録は応答が完了した直後に行います。中断された実行は自動記録せず、ノート作成自身の完了では再発火しません。
- ノートはモデルが通常のファイルツールを使い、[procedure.md](procedure.md) に従って作成・更新します。会話の全文バックアップではなく、内容や保存成功は保証されません。失敗時の自動再試行はありません。
- 記録のために追加のモデル実行が発生し、時間と利用料金がかかります。ノート作成中の成功したツール表示は抑制しますが、履歴には残り、セッション再開後などに表示されることがあります。
- 手順では認証情報や不要な個人情報を転記しないようモデルに指示していますが、確実な除外は保証されません。ノートには会話内容やセッションファイルのパス、作業ディレクトリが含まれ得るため、保存先へのアクセスを制限し、Git 管理や共有の前にノートの内容を確認してください。
- `guard:trust-dir` イベントで、通常ノートの親ディレクトリをセッション開始時に、各保存先の親ディレクトリをそれぞれの保存依頼時に通知します。実際の許可範囲や動作は guard 側の実装と設定に依存します。

## テスト

```sh
npm ci
npm run typecheck
npm test
npm run check:package
```

開発時の基準バージョンは `.nvmrc` の Node.js 26 です。CI は最低対応版の 22.19.0 と、24・26 系でも実行します。テストはコマンドやイベントの処理、保存先の解決に加え、偽モデルを使った Pi セッションでの保存依頼とファイルツール実行を検証します。実際のモデルによる記録品質や guard との連携は検証しません。
